# Quickstart: Conversational Adventure MVP

**Feature**: 001-conversational-adventure-mvp | **Date**: 2026-08-31

This guide validates that the MVP works end-to-end. It does not contain implementation code — see `data-model.md` and `contracts/` for structural detail, and `tasks.md` (generated by `/speckit-tasks`) for build-out steps.

## Prerequisites

- .NET 10 SDK installed.
- Docker (for local PostgreSQL + Azurite blob emulator containers).
- An Azure AI Foundry / Azure OpenAI deployment (chat + image generation) reachable from local dev, with credentials available via user-secrets (never committed to source control), per constitution Principle XV.

## Setup

1. Restore and build the solution:
   ```powershell
   dotnet restore
   dotnet build
   ```
2. Start local infrastructure (PostgreSQL + Azurite) via the provided local compose file (to be added under `tasks.md`'s infra tasks).
3. Configure local secrets for the `AI.SpectrumAdventure.Web` project:
   ```powershell
   dotnet user-secrets set "ConnectionStrings:AdventureDb" "Host=localhost;Database=adventure;Username=postgres;Password=postgres"
   dotnet user-secrets set "AzureAI:Endpoint" "<your-foundry-endpoint>"
   dotnet user-secrets set "AzureAI:ApiKey" "<local-dev-only-key>"
   ```
4. Apply EF Core migrations:
   ```powershell
   dotnet ef database update --project src/AI.SpectrumAdventure.Infrastructure --startup-project src/AI.SpectrumAdventure.Web
   ```
5. Run the app:
   ```powershell
   dotnet run --project src/AI.SpectrumAdventure.Web
   ```

## Manual validation scenarios

These map directly to the feature spec's acceptance scenarios (User Stories 1–10) and the constitution's required acceptance tests.

### 1. Start Game (spec US1, constitution "Start Game")

- Open the app in a browser. **Expect**: player is placed at Forest Entrance, sees a narrative description (atmosphere, exits, at least one interactive element) and a retro 8-bit visual for that location without additional input.

### 2. Location description consistency (spec US2)

- Type `look` twice in a row without taking any other action. **Expect**: identical factual content (exits, objects, characters) in both responses.

### 3. Classic commands (spec US3, constitution "Movement" / "Invalid Movement")

- Type `go north` from Forest Entrance. **Expect**: player moves to Dark Forest, sees its description.
- Type `go south` from Forest Entrance (no such exit). **Expect**: world state unchanged, meaningful explanation returned (`ActionResult.reason = NoSuchExit`).

### 4. Natural language (spec US4)

- Type `I carefully inspect the door for traps.` **Expect**: recognized as an Examine-style intent, in-world response.
- Type an implausible action (e.g., `I fly to the moon.`). **Expect**: stateless, in-character rejection (`reason = ImpossibleAction`), no state change, same response if repeated.

### 5. Take Item (spec US7, constitution "Take Item")

- Navigate to a location with a collectible item and type `take <item>`. **Expect**: item appears in inventory (`inventory` command), removed from location's visible items.

### 6. Use Missing Item (spec edge case, constitution "Use Missing Item")

- Attempt `use <item-you-do-not-have>`. **Expect**: action fails safely (`reason = ItemNotInInventory`), world state unchanged.

### 7. NPC interaction (spec US8)

- Navigate to Dark Forest, initiate conversation with the NPC across at least 3 turns, including one generic/unsure question. **Expect**: consistent personality, no leaked out-of-scope knowledge, at least one proactively suggested topic (Clarification Q3).

### 8. Solve Puzzle (spec US9, constitution "Solve Puzzle")

- Attempt to enter the Forgotten Tower before satisfying both conditions. **Expect**: consistently blocked with explanation.
- Obtain the item at Old Bridge and learn the clue from the NPC, then use the item at the tower entrance. **Expect**: puzzle solves, entrance becomes accessible, change persists on repeated visits.

### 9. Retro visual updates (spec US10, constitution "Image Generation Failure")

- Enter each of the four locations for the first time. **Expect**: a retro 8-bit visual is shown for each.
- Trigger the tower-unlock scene change. **Expect**: an updated visual reflects the new scene without delaying the narrative response.
- Simulate an image pipeline failure (e.g., via a test double). **Expect**: gameplay continues uninterrupted; narrative response is unaffected; the failure is observable in telemetry (Decision 8).

## Success criteria checklist

Cross-reference with `spec.md`'s Success Criteria (SC-001 through SC-010) after completing the manual scenarios above; all must be satisfiable without contradicting previously established facts across at least 15 turns in a single continuous session (per Clarification Q2).
